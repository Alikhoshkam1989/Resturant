Authentication and responses

This REST API manages a restaurant's menu, tables, reservations, orders and invoices. Base URL: http://localhost:8080. Import exports/restaurant.postman_collection.json into Postman.

Use Authorization Code + PKCE (S256) for login and registration. Keycloak realm: http://localhost:8081/realms/restaurant. Client: restaurant-postman. Postman callback: https://oauth.pstmn.io/v1/callback. Authorization path: /protocol/openid-connect/auth. Token path: /protocol/openid-connect/token. Scope: openid profile email.

Local demo accounts: klant / Klant-Demo-2026! (CUSTOMER), personeel / Personeel-Demo-2026! (STAFF). New registrations receive CUSTOMER. A Keycloak administrator grants STAFF separately. These credentials are for local demonstrations only.

Authorization: Bearer <access_token>
Content-Type: application/json

GET returns 200, POST returns 201 with Location, PUT returns 200 (image uploads: 204), DELETE returns 204. Errors: 400 invalid input, 401 missing or invalid token, 403 insufficient permission or ownership, 404 missing resource, 405 unsupported method, 409 conflict, 413 upload too large, 415 unsupported content type. Application errors use ProblemDetail; security-filter errors may have an empty body.

{"type":"about:blank","title":"Conflict","status":409,
 "detail":"Table is reserved during this time slot"}

IDs are positive database identifiers. Lists are JSON arrays; individual resources are JSON objects. Dates are UTC without a suffix, for example 2030-12-01T17:00:00. Prices are final amounts in EUR. No list filters or pagination are supported. Choose a future date when testing reservations.

Resource endpoints

Each resource below supports GET /api/{resource} (list), GET /api/{resource}/{id} (one item), POST /api/{resource} (create), PUT /api/{resource}/{id} (update), and DELETE /api/{resource}/{id} (delete or cancel). Replace {resource} with the name in the table. GET returns 200 or 404 for a missing item. POST returns the created object and Location. PUT returns the updated object. DELETE returns 204 or 409 when a business rule prevents deletion.

For resources other than invoices, PUT uses the same input fields as POST. Response-only fields are managed by the server.

Input validation

  • Category: name is required, nonblank, unique and at most 80 characters. Description is required and at most 500 characters.
  • Product: name is required and at most 100 characters. categoryId must exist. price is required, nonnegative, with at most eight integer and two decimal digits. available is a required boolean.
  • Table: tableNumber must be unique and at least 1. seats must be between 1 and 50. available is required. Capacity cannot be reduced while reservations are linked. Disabling availability does not cancel existing reservations.
  • Reservation: customerName is required and at most 100 characters. tableId must exist. startsAt must be in the future. guests must be between 1 and 50 and fit the table. remarks is required and at most 1000 characters. Ownership is taken from the token; endsAt and cancelled are server-managed.
  • Order: tableId must identify an available table. lines must contain 1 to 100 non-null items. Each productId must exist and be available; quantity must be between 1 and 100. Duplicate products are rejected. total and createdAt are server-managed.
  • Invoice: POST requires orderId referring to an order without an invoice. PUT requires a boolean paid value. Amount and date are server-managed.

Invalid JSON inputs return 400; missing references return 404. Overlaps, duplicate names/numbers and blocked changes return 409. SQL and internal exception details are not returned to clients.

Images and permissions

PUT /api/products/{productId}/image: STAFF uploads a multipart/form-data body with file field file. Success returns 204. Only PNG/JPEG up to 2 MiB and 16 million pixels are allowed. Empty or corrupt images return 400; oversized files return 413; unsupported formats return 415. Client filenames are never used as filesystem paths.

curl.exe -X PUT http://localhost:8080/api/products/1/image ^
 -H "Authorization: Bearer TOKEN" -F "file=@product.png"

GET /api/products/{productId}/image: CUSTOMER and STAFF receive image bytes with image/png or image/jpeg Content-Type and a safe attachment filename. A missing image returns 404.

Public pages: GET /, /index.html and /api-docs.html. Unauthenticated API requests return 401. CUSTOMER can read the catalog, tables and images and manage their own reservations. STAFF can access all API endpoints. Unknown realm roles have no API access.

Keycloak administrators manage accounts and roles but are not a separate API role. JWTs require a valid signature, configured issuer, subject and restaurant-api audience.
